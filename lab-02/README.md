# Питання в задачах

## Task 1

1. open()

Відкриває файл і повертає файловий дескриптор — ціле число, яке використовується для подальшої роботи з файлом.

У програмі:
fd = open(path, O_WRONLY | O_CREAT | O_TRUNC, 0644);

Аргументи:
- path — шлях до файла.
- O_WRONLY — відкрити файл для запису.
- O_CREAT — створити файл, якщо він не існує.
- O_TRUNC — очистити файл, якщо він уже існує.
- 0644 — права доступу до нового файла.
Результат:
- Успіх — повертає файловий дескриптор (невід'ємне число).
- Помилка — повертає -1 і встановлює errno.
2. write()

Записує дані у файл.
write(fd, line, strlen(line));

Аргументи:
- fd — файловий дескриптор.
- line — дані, які потрібно записати.
- strlen(line) — кількість байтів для запису.
Результат:
- Успіх — повертає кількість фактично записаних байтів.
- Помилка — повертає -1.
3. close()

Закриває файловий дескриптор.
close(fd);

Аргумент:
- fd — дескриптор файла.
Результат:
- Успіх — повертає 0.
- Помилка — повертає -1.
4. read()

Зчитує дані з файла.
n = read(fd, buffer, sizeof(buffer) - 1);

Аргументи:
- fd — файловий дескриптор.
- buffer — буфер, у який записуються дані.
- sizeof(buffer) - 1 — максимальна кількість байтів для читання.
Результат:
- Позитивне число — кількість прочитаних байтів.
- 0 — досягнуто кінця файла.
- -1 — помилка.
5. lseek()

Змінює поточну позицію читання або запису у файлі.
lseek(fd, 11, SEEK_SET);

Аргументи:
- fd — файловий дескриптор.
- 11 — зміщення в байтах.
- SEEK_SET — відлік від початку файла.
Результат:
- Успіх — повертає нову позицію у файлі.
- Помилка — повертає -1.
Важливо: lseek() не змінює вміст файла. Він лише переміщує позицію, з якої відбуватиметься наступне читання або запис.

## Task 3

Чому записується саме n байтів, а не 4096?
У програмі використовується буфер:

`char buf[4096];`

Він може зберігати максимум 4096 байтів. Однак функція read() не обов'язково заповнює весь буфер. Наприклад, якщо у файлі залишилося лише 18 байтів, вона поверне 18. Тому запис виконується так:

`write(out, buf, n);`

Якщо записувати всі 4096 байтів, у вихідний файл потраплять зайві дані з буфера, які не були отримані під час читання.

# Питання для захисту

1. Що таке файловий дескриптор і що повертає open у разі помилки?

Файловий дескриптор — це невід'ємне ціле число, яке операційна система використовує для ідентифікації відкритого файла або іншого ресурсу. У разі помилки open() повертає -1.

2. Для чого потрібні прапорці O_CREAT і O_TRUNC?

O_CREAT створює файл, якщо він не існує. O_TRUNC очищає вміст наявного файла під час відкриття для запису.

3. Що змінює виклик lseek?

Він змінює поточну позицію читання або запису у файловому дескрипторі. Сам вміст файла не змінюється.

4. Чому у copy_file записують рівно n байтів, а не 4096?

Тому що read() повертає фактичну кількість прочитаних байтів. Решта буфера може містити неактуальні дані.

5. Чи можна виконати ці операції без системних викликів, лише функціями бібліотеки?

Можна використовувати стандартні функції бібліотеки C, наприклад fopen(), fread(), fwrite(), fseek() та fclose(). Але вони працюють поверх системних викликів операційної системи. Тобто повністю уникнути системних викликів під час звичайної роботи з файлами не вийде.
