## Завдання 1

Пояснення роботи програми:
- getpid() повертає ідентифікатор поточного процесу.
- getppid() повертає ідентифікатор батьківського процесу.
- fork() створює новий процес — нащадок отримує копію адресного простору батька.
- execlp() замінює програму нащадка іншою програмою. У цьому випадку запускається команда echo.
- waitpid() змушує батьківський процес дочекатися завершення конкретного нащадка.
- WIFEXITED() перевіряє, чи завершився процес звичайним способом.
- WEXITSTATUS() отримує код завершення.
- WIFSIGNALED() перевіряє, чи завершився процес через сигнал.
- WTERMSIG() повертає номер сигналу.
Чому fork() повертає різні значення?

fork() повертає:
- 0 — у процесі-нащадку;
- PID нащадка — у батьківському процесі;
- -1 — якщо створити процес не вдалося.
Це дозволяє програмі визначити, у якому процесі вона виконується.

Чому після успішного exec() код не виконується?

Тому що exec() повністю замінює поточний образ програми новою програмою. Процес продовжує існувати, але вже виконує інший код.

Якщо execlp() завершується успішно, керування більше не повертається до старої програми. Тому perror() та _exit(127) виконуються тільки тоді, коли запуск програми не вдався.

Для чого потрібен fflush(NULL)?

Він очищає всі вихідні буфери стандартних потоків. Це важливо перед fork() та exec(), щоб буферизований текст не дублювався або не губився.

Що означає waitpid(pid, &status, 0)?
- pid — PID процесу, завершення якого потрібно очікувати.
- &status — адреса змінної, куди буде записано інформацію про завершення.
- 0 — процес очікує завершення нащадка без додаткових параметрів.

## Завдання 2

В першому варіанті вивід ls -l з'являється між повідомленням нащадка та повідомленням батька. Це відбувається тому, що батьківський процес очікує завершення нащадка за допомогою waitpid().

В другому варіанті функція execlp() намагається знайти програму за вказаним ім'ям у каталогах, перелічених у змінній середовища PATH.

Оскільки програми no-such-program-xyz не існує, функція повертає помилку.

perror("execlp") виводить повідомлення про причину помилки. У цьому випадку це No such file or directory.

Після помилки виконується _exit(127). Код 127 використовується в цій програмі як позначення невдалого запуску іншої програми.

## Завдання 3

Програма створює три дочірні процеси за допомогою циклу for.

Кожен процес виконує sleep(1), тобто очікує одну секунду.

Далі відбувається перевірка номера нащадка:
- Нащадок 0: завершується за допомогою _exit(10). Код завершення — 10.
- Нащадок 1: виконує abort(), що призводить до аварійного завершення через сигнал SIGABRT. У Linux його номер — 6.
- Нащадок 2: завершується за допомогою _exit(12). Код завершення — 12.
Функція _exit() завершує процес без виконання обробників atexit() та без очищення стандартних потоків. У цій програмі це дозволяє безпосередньо передати код завершення батьківському процесу.
Чи завжди повідомлення з'являються в однаковому порядку?
У цій програмі батьківський процес використовує:
```
waitpid(pids[i], &status, 0);
```

Виклики виконуються послідовно за індексами 0, 1, 2.

Тому звіт завжди виводиться в такому порядку:
1. Нащадок 0.
2. Нащадок 1.
3. Нащадок 2.
Проте самі дочірні процеси можуть завершуватися в іншому порядку. Це залежить від планувальника операційної системи.

Важливо розуміти різницю: порядок завершення процесів не обов'язково збігається з порядком отримання їхніх статусів батьківським процесом.


## Відповіді на питання для захисту

1. Що повертає fork батьківському процесу, а що — нащадкові?

Функція fork() створює новий дочірній процес. Батьківський процес отримує PID створеного нащадка, а дочірній процес отримує значення 0. Якщо створити процес не вдалося, повертається -1.

2. Чому після успішного exec код, що йде далі, не виконується?

Тому що exec() замінює поточну програму іншою. Процес продовжує працювати, але вже виконує нову програму. Якщо запуск успішний, функція не повертає керування старому коду.

3. Що повертає waitpid і що містить змінна status?

waitpid() повертає PID процесу, завершення якого було очікувано. Якщо виникла помилка, повертається -1.

Змінна status містить інформацію про завершення процесу. За допомогою спеціальних макросів можна визначити, чи завершився він нормально, чи через сигнал, а також отримати відповідний код або номер сигналу.

4. Чим відрізняється нормальне завершення процесу від завершення сигналом і як це визначити макросами WIFEXITED / WIFSIGNALED?

Нормальне завершення відбувається тоді, коли програма самостійно завершує роботу, наприклад через return 0 або _exit(0).

Завершення сигналом відбувається тоді, коли процес отримує сигнал, який призводить до його зупинки. Наприклад, функція abort() викликає сигнал SIGABRT.

Для перевірки використовуються:
- WIFEXITED(status) — перевіряє нормальне завершення.
- WEXITSTATUS(status) — отримує код нормального завершення.
- WIFSIGNALED(status) — перевіряє завершення через сигнал.
- WTERMSIG(status) — отримує номер сигналу.
